# KOBIS Digital Launch Hub

> **Maturity: multi-project demonstration repository — delivery toolkit and static business prototypes**

KOBIS Digital Launch Hub is a working collection of independent website concepts, reusable delivery material and lightweight assessment experiences. It demonstrates how multiple small-business ideas can move from brief to testable interface while keeping each product’s scope visible.

This repository is not one production platform, a client-management system or a live AI service. Each contained site should be evaluated and deployed independently.

## Business problem

Early-stage business teams often need to test positioning, customer journeys and calls to action before investing in a full operational system. Delivery teams also need repeatable structures for briefs, content, design, review and deployment without presenting prototype material as established commercial evidence.

## Intended users

- business owners reviewing a digital concept
- delivery teams building and comparing early product directions
- programme managers assessing prototype scope
- portfolio reviewers examining product and workflow breadth

These are intended users of the approach, not evidence of customers, contracts, adoption or commercial outcomes.

## What the repository demonstrates

The inspected repository contains separate examples including:

- a browser-based client assessment and roadmap experience
- static business and campaign sites for fragrance, grooming, automotive, farming, food and related concepts
- a proposal-style microsite
- WhatsApp-oriented enquiry handoffs
- a Decap CMS content configuration in one project
- project indexes, delivery prompts and repository-level working guidance
- selected GitHub Actions and Netlify deployment configuration
- locally vendored Claude Code workflow and skill material

The sites are portfolio demonstrations with different levels of completeness. A business name, person, testimonial, metric, logo or service claim inside a prototype is not proof of a client relationship, permission, performance or endorsement.

## Strategic value

The hub provides a practical place to compare reusable patterns across discovery, assessment, content and conversion journeys. Its strongest value is as delivery evidence: it shows structured prototyping across several business contexts and makes gaps easier to identify before a project is separated into a governed product repository.

## Technology and architecture

The collection primarily uses:

- HTML, CSS and browser JavaScript
- local browser state and deterministic interface logic
- WhatsApp links and form-oriented calls to action
- Decap CMS configuration and structured content in selected examples
- GitHub Actions and Netlify-oriented deployment files
- Markdown-based delivery documentation and local agent-workflow configuration

There is no single shared backend, authentication layer, database or runtime AI model evidenced across the hub. “AI-assisted” refers to the delivery workflow and supporting tools, not an autonomous customer-facing capability.

## Responsible use and limitations

- **Validate every public claim.** Names, registrations, services, testimonials, metrics, pricing, credentials, logos and partner references must be approved by the relevant owner before publication.
- **Separate real engagements from concepts.** Each project needs its own evidence record, content owner and approval status.
- **Do not collect sensitive data without a governed backend.** Most inspected experiences are static or browser-local and do not evidence production authentication, authorisation, retention or deletion controls.
- **Review third-party assets and tooling.** Vendored skills, fonts, images, libraries and templates require licence, attribution and provenance checks before reuse.
- **Test contact and conversion paths.** WhatsApp links, forms, CMS workflows and deployments need environment-specific validation.
- **Apply accessibility and language review.** Keyboard use, contrast, responsive behaviour and multilingual claims need project-level testing.
- **Keep projects isolated.** Production candidates should move to separate repositories with explicit owners, secrets management, deployment controls and change history.

## Portfolio position

This is a breadth-and-process repository, not a flagship product claim. Individual concepts should enter the main portfolio only after their identity, evidence, permissions, security posture and public demonstration have been reviewed independently.
